# write-readme

처음 온 독자가 README 상단에서 세 가지를 알 수 있게 쓴다. **무엇인가**, **내 상황에 쓸 수 있는가**, **어디서 무엇을 하면 시작되는가**.

## 1. 독자와 근거 확인

- 누가 어떤 일을 하러 오는지부터 정한다. 기존 README와 `AGENTS.md`, 실제 설정·코드·사용 문서에서 시작 경로와 결과를 확인한다.
- 대표 독자의 가장 흔한 시작 경로를 상단에 둔다. 새 사용자와 기존 사용자처럼 첫 행동이 달라지는 경우에는 상황을 제목으로 써서 필요한 경로를 찾게 한다.

## 2. 시작 안내 작성

- 복사해 쓸 수 있는 첫 행동을 보여 준다. 웹앱은 접속 주소, 에이전트 도구는 저장소를 가리키는 짧은 요청문, 앱은 설치 위치, 라이브러리·CLI는 설치와 최소 실행 예시를 쓴다. 어디에 입력하는지와 다음에 어떤 일이 일어나는지 알려 준다.
- 에이전트가 요청을 보고 스킬을 고를 수 있다면, 복사용 예시에는 원하는 작업만 쓰고 스킬 이름은 예시 아래에 안내한다.
- 시작을 막는 필수 조건과 승인 여부는 해당 단계에 붙인다. 선택 설치, 세부 규칙, 유지보수 절차는 필요한 자리에서 원본 문서에 링크한다.
- 독자가 선택하거나 실행하는 데 필요한 설명만 남긴다. 낯선 용어는 쓰는 자리에서 짧게 풀고, 화면 예시는 실제 화면이 사용법을 설명할 때 넣는다. 저장소의 언어 정책과 다국어 사본은 함께 맞춘다.

## 3. 자체 검수

- 처음 온 독자처럼 상단부터 읽고, 대표 상황마다 첫 행동을 바로 찾을 수 있는지 확인한다. 긴 개요를 읽어야 예시가 나오거나 같은 설명이 반복되면 배치를 바꾼다.
- 예시의 경로·명령·결과는 코드·설정·공식 문서와 대조한다. 가능하면 실제 사용 경로를 실행하고, 변경 권한이나 실행 환경이 없으면 확인한 근거와 검증 범위를 보고한다.
- 링크와 이미지 경로를 확인하고, 가능한 경우 렌더링을 확인한다. 낡은 정보·중복·모순 점검은 [audit-docs](../audit-docs/SKILL.md)를 따른다.
