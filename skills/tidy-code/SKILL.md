# tidy-code

동작을 바꾸지 않고 코드·CSS·테스트를 더 짧고 단순한 구조로 정리한다. 큰 변경 뒤에는 요청이 없어도 한다. 기능 추가·동작 변경은 이 스킬의 일이 아니다.

## 1. 범위와 기준선

- 범위는 사용자가 준 곳만이다. 없으면 최근 변경이 많았던 파일(`git log --stat`)부터 본다.
- 정리 전에 프로젝트의 테스트·빌드 명령(`AGENTS.md`의 "실행과 검증")을 **새로 실행**해 통과 상태를 확인한다. 이미 실패하면 정리하지 말고 보고한다. 명령이 없으면 기준선이 없다고 먼저 보고하고 범위를 줄인다.
- 미커밋 변경이 있으면 사용자 작업인지 확인하고, 그 파일은 건드리지 않는다.

## 2. 찾는다

변경 전에 목록부터 만든다. 삭제 후보는 이름 검색(`grep`)으로 참조 0건임을 확인한 것만 올린다.

- **미사용**: 호출되지 않는 함수·변수·파일·의존성, 쓰이지 않는 CSS 선택자·규칙, 막힌 분기, 주석 처리된 코드.
- **중복**: 같은 로직의 복사본, 거의 같은 컴포넌트, 값만 다른 CSS 블록.
- **구조**: 한 함수·파일이 여러 일을 하는 곳, 깊게 얽힌 조건, 기본 구조 없이 케이스마다 따로 붙은 CSS(공통 기본 규칙 + 변형으로 합칠 수 있는지), 낡은 방식.
- **테스트**: 베이스라인 "코드와 테스트" 구역 기준으로 극단 상황 가정, 다른 테스트와 같은 것을 확인하는 것, 구현 세부에 묶인 것.

## 3. 고친다

- 한 묶음(미사용 삭제, 중복 통합, 구조 분리, 테스트 정리)씩 고치고, 묶음마다 테스트·빌드를 새로 실행한다. 깨지면 그 묶음을 되돌리고 원인을 보고한다.
- 중복 테스트는 통합하고, 중요도가 낮은 극단 상황 테스트는 삭제 후보로 사용자에게 보고한다. 지우기 전에 그 테스트가 막는 회귀가 있는지 읽고 판단한다.
- 동작이 바뀔 수 있는 수정과 공개 인터페이스 변경은 고치지 말고 결정 항목으로 남긴다.
- 정리 중 떠오른 기능 추가·새 추상화는 하지 않고 목록으로만 알린다.
- 커밋은 사용자가 요청할 때 묶음별 의미 단위로 한다.

## 4. 보고한다

"한 일 / 확인하지 못한 것 / 하지 않은 것"으로 나누고, 사용자가 결정할 항목을 맨 위에 둔다. 줄어든 규모(삭제한 파일·줄·테스트 수)와 정리 전후 테스트·빌드 결과를 쓴다. 문자열로 조립하는 클래스명처럼 검색으로 확인하지 못한 동적 참조는 "확인하지 못한 것"에 쓴다.
