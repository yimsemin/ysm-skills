# share-lesson

한 프로젝트 세션에서 해결한 문제의 교훈을 뽑아, 다른 프로젝트의 에이전트에 붙여 넣을 블록으로 만든다. 행선지는 제안까지만 하고 파일은 바꾸지 않는다. 해결한 세션이 끝나기 직전에 쓴다. 맥락이 그 세션에 가장 많이 남아 있기 때문이다.

## 1. 재료와 판단

현재 대화와 변경 내용(`git diff`, `git log`)만 쓴다. 세션이 이미 끝났으면 사용자가 붙여 준 내용이나 지정한 대화만 쓰고, 세션 로그 폴더를 직접 뒤지지 않는다. 원인을 확인하지 못했으면 추정이라고 표시한다.

다음에도 겪을 만하고 원인이 확인된 문제만 교훈으로 삼는다. 한 번뿐인 사정이면 "남길 교훈 없음"으로 끝낸다.

## 2. 일반화

저장소 밖으로 나가도 되는 내용만 남긴다. 개인 경로, 사용자 이름, 회사·프로젝트 이름, 비밀값, 내부 주소를 지우고, 고유 이름은 역할로 바꾼다(`설정 파일`, `배포 스크립트`). 출력을 인용할 때는 신호가 되는 줄만 쓰고 비밀값은 `<REDACTED>`로 가린다.

## 3. 붙여넣기 블록

코드 블록 하나로 쓴다. 이 대화를 보지 못한 에이전트가 혼자 읽고 움직일 수 있어야 하므로 "위에서 말한"처럼 대화를 가리키지 않는다.

- **제목**: 한 줄.
- **증상**: 어떤 상황에서 무엇이 보이는지.
- **원인**: 확인한 사실과 추정을 구분.
- **해당 여부 확인**: 이 프로젝트가 영향받는지 보는 읽기 전용 명령이나 파일 위치. 필수 항목이다.
- **수정**: 단계별.
- **수정 뒤 확인**: 실행할 명령과 기대 결과.
- **받는 쪽 지시**(고정 문장): "먼저 '해당 여부 확인'만 실행해 결과를 보고하고, 해당할 때만 수정하라. 해당하지 않으면 적용하지 말고 이유를 보고하라. 커밋은 사용자가 요청할 때만 한다."

## 4. 행선지 제안

교훈마다 하나를 고르고 근거를 쓴다.

- **붙여넣기만(기본값)**: 다른 프로젝트 몇 곳을 한 번 고치면 끝나는 경우.
- **베이스라인 후보**: 다른 프로젝트에서도 해당함이 확인됐거나 확인되는 시점. 규칙 문장보다 자동 검사(훅·스크립트)를 먼저 검토한다. 반영은 ysm-skills 저장소에서 `baseline/`을 고치고, 전역 지침과 겹치는 문장이 없는지 확인한다.
- **스킬 후보**: 반복되는 절차. 기존 스킬에 합칠 수 있는지 먼저 본다.
- **이 프로젝트의 `docs/`**: 이 프로젝트에만 해당하는 경우.

## 5. 보고

결론(교훈 있음·없음, 제안한 행선지)을 첫 줄에, 사용자가 결정할 항목을 바로 아래에 쓴 뒤 블록을 붙인다. 보고는 "한 일 / 확인하지 못한 것 / 하지 않은 것"으로 나눈다. 다른 프로젝트에 해당하는지 확인하지 않았다는 점과 원인 추정 부분을 빠뜨리지 않는다.
