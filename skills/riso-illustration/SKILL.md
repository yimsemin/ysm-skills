# riso-illustration

화풍은 `references/style.md`에 한 번 정해 두었으므로 사용자가 매번 설명하지 않는다. 이 스킬은 주제 → 후보 → 선택 → 부분 수정의 순서만 다룬다. 시작 전에 `references/style.md`를 읽는다.

## 1. 요청 정리

사용자 말에서 아래만 뽑고, 빠진 것은 묻지 말고 가정해 밝힌다.

- **주제와 장면**: 무엇을 어떤 상황으로 보여 줄지. 개념 비유면 어떤 비유인지 한 줄로 정한다.
- **용도와 비율**: 프로필 1:1, 웹 장면 3:2 또는 16:9. 사용처·사용자 지시가 우선한다.
- **팔레트**: 말이 없으면 기본(`style.md`). 색이나 분위기를 말하면 화풍은 두고 색만 바꾼다.
- **참고 이미지**: 사용자가 이번 작업에 준 것만 쓴다. 저장소·스킬 폴더에 복사하지 않는다.
- **개수**: 말이 없으면 4장.

## 2. 도구 확인

이 세션에 이미지를 생성·편집하는 도구가 있는지 확인한다. 없는 것을 설치·연결하거나 새 API·유료 서비스·MCP 서버를 쓰자고 하지 않는다.

- **있음**: 실제로 생성한다. 참고 이미지는 그 도구가 받을 때만 넘긴다(외부로 전송된다는 점을 사용자가 아는 경우만).
- **없음**: 생성하지 못했다고 첫머리에 밝히고 3절의 프롬프트와 옵션(비율, 후보별 차이)만 낸다.

## 3. 후보 만들기

`style.md`의 프롬프트 골격으로 후보마다 프롬프트를 따로 쓴다.

- 후보마다 **구도·시점·동작·소품·장면 구성 중 둘 이상**이 실질적으로 달라야 한다. 같은 장면의 미세 변형은 후보가 아니다.
- 화풍·팔레트·"글자 없음"은 모든 후보에 같게 둔다. 인물의 성별·복장·포즈·배경은 요청에 맞춰 후보마다 정한다.
- 후보는 한 장씩 별도 파일이다. 사용자가 요청하지 않으면 격자로 합치지 않는다.
- 파일은 사용처가 정한 위치에, 없으면 프로젝트 안 `illustrations/<주제>/`에 `후보-1`, `후보-2`…로 저장한다. 프로젝트 밖에 두지 않는다.

## 4. 제시

번호를 붙여 한 줄씩 차이를 적는다("1 정면 클로즈업, 2 책상 위 조감…"). 생성했으면 파일 경로를, 못 했으면 번호별 프롬프트를 코드 블록으로 준다. 사용자가 고르거나 수정 방향을 말하면 5절로 간다.

## 5. 선택과 수정

선택한 후보의 프롬프트와 파일을 기준으로 삼는다. 요청한 부분만 바꾸고 나머지(구도, 인물 특징, 팔레트)는 유지하도록 프롬프트에 "유지할 것"을 명시한다.

- 편집을 지원하는 도구면 선택 이미지를 입력으로 편집한다. 아니면 선택 후보의 프롬프트에 변경점을 더해 다시 생성한다.
- 수정도 후보 2~4장이 기본이다. 사용자가 한 장만 원하면 한 장.
- 선택이 안 났거나 마음에 드는 후보가 없으면, 어떤 점이 아쉬운지 묻기보다 `style.md`의 검수 기준으로 원인을 짚어 다음 라운드를 제안한다.

## 6. 검수와 보고

생성한 이미지는 `style.md`의 검수 기준으로 직접 보고 어긋난 것을 알린다(예: 글자가 들어감, 매끈한 벡터 느낌). 보고는 "한 일 / 확인하지 못한 것 / 하지 않은 것"으로 나눈다. 생성 도구가 없었거나, 실제로 보지 못한 이미지가 있으면 반드시 쓴다.
