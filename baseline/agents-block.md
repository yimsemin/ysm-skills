## 공통 작업 규칙 (ysm baseline)

이 구역은 ysm-skills 베이스라인이 관리한다. 프로젝트 고유 규칙은 이 구역 밖에 쓰고, 이 구역과 충돌하면 프로젝트 규칙이 우선한다.

### 작업 방식

- 별도 지시가 없으면 한국어로 소통한다. 코드 식별자·파일명·표준명은 원문을 쓴다.
- 요청한 범위만 최소 변경으로 한다. 요청하지 않은 기능·의존성·추상화·파일·공개 범위를 추가하지 않고, 떠오른 개선은 하지 말고 목록으로만 알린다.
- 삭제·덮어쓰기 전에 대상을 확인하고 사용자의 기존 변경을 보존한다. 남의 변경을 임의로 `reset`·`clean`·`stash`하지 않는다.
- 같은 규칙을 여러 문서에 복사하지 않고 정본 한 곳을 링크한다. 문서에는 현재 결정만 남긴다.
- 완료 보고에는 변경 내용, 실제로 실행한 검증, 남은 결정과 한계를 적는다. 실행하지 않은 검사를 통과했다고 쓰지 않는다.
- 에이전트가 켠 서버·프로세스는 작업이 끝나면 끈다.

### Git

- stage·commit·push·PR·merge는 사용자가 요청할 때만 한다. 승인은 그 요청에만 유효하고 다음 작업으로 이어지지 않는다. 이 파일의 프로젝트 구역이 명시한 상시 승인만 예외다.
- force push, 푸시한 이력의 수정, 브랜치·태그 강제 삭제, 공유 브랜치의 `reset --hard`는 사용자가 그 대화에서 직접 요청했을 때만 한다. 푸시 전 로컬 커밋의 amend·fixup 정리는 이력 재작성이 아니다. `--no-verify`로 훅을 우회하지 않는다.
- 첫 커밋 이후의 작업은 `main`이 아닌 작업 브랜치(`feat/` `fix/` `docs/` `chore/` + kebab-case)에서 한다. 프로젝트가 `main` 직행을 명시하면 예외다. 병렬 작업은 브랜치마다 `git worktree`로 분리한다.
- 커밋은 의미·작업 단위 하나씩 만든다. 같은 목적의 후속 수정(오타·누락·리뷰 반영)은 새 커밋으로 쌓지 말고 푸시 전에 amend·fixup으로 합친다.
- 커밋 제목은 `<type>(<선택 scope>): <요약>`이다. type은 `feat` `fix` `perf` `refactor` `docs` `test` `build` `ci` `chore` `style` `revert`, 72자 이내, 끝에 마침표 없음. 이유가 필요하면 본문에 쓴다. 제목 언어는 프로젝트가 정한다.
- PR 본문은 요약(무엇을·왜), 확인한 방법(실제 실행한 것만), 남은 결정 순서로 짧게 쓴다(`.github/pull_request_template.md`).
- 커밋 메시지와 PR 본문에 AI 생성 표식이나 co-author 트레일러(`Co-Authored-By: Claude …`, `🤖 Generated with …` 등)를 넣지 않는다. `.githooks/commit-msg`가 커밋에서 제거하지만 PR 본문은 훅이 못 막으므로 직접 지킨다.
- 새 클론에서는 한 번 `git config core.hooksPath .githooks`를 실행한다(Claude Code는 세션 시작 때 자동 실행).

### 의존성과 환경

- 전역 설치를 하지 않는다. 의존성·가상환경·캐시·데이터·설정·로그는 프로젝트 폴더 안에만 두어, 폴더를 지우면 함께 사라지게 한다. 폴더 밖 저장은 사용자가 명시적으로 고른 경우만 허용한다.
  - Node: `package.json`의 `devDependencies`와 `npx`. `npm install -g` 금지.
  - Python: `uv`로 프로젝트 `.venv`만 쓴다(`uv sync`, `uv add`). 가상환경 밖 `pip install` 금지.
  - 런타임 버전은 `.node-version`, `.python-version`에 고정한다.
- 전역으로 허용되는 도구: `git`, `gh`, `mise`, `uv`, `claude`, `codex`, `brew` 자체. 그 밖의 전역 설치는 사용자가 명시적으로 요청했을 때만 한다.
- macOS와 Windows에서 같은 동작을 하도록 플랫폼 중립 경로와 LF 줄바꿈을 쓴다.

### 안전

- 저장소는 언제 공개되어도 문제가 없는 상태로 유지한다. `.env`, 키, 토큰, 개인정보, 개인 절대경로, 실제 업무 문서를 저장소에 넣거나 읽어 출력하지 않는다. 환경변수 예시는 값이 없는 `.env.example`만 둔다.
- 비밀값으로 보이는 파일·문자열이 staged에 있으면 `.githooks/pre-commit`이 커밋을 막는다.
